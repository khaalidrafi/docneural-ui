  1. 13.3.16 mpv Media Player

    Configuring the mpv media player can be somewhat daunting task, due to the sheer amount of options available, especially if one wants to be able to inherit the configuration in their code. The home-mpv-service-type is provided to help with that problem. When the service is added to your home environment, file based on the passed configuration is generated and placed into the correct location.

    Due to the bug #74748, it does not use Guix Records to represent the configuration, but uses keyword arguments to achieve similar result. Example follows: 

    (service home-mpv-service-type
         (make-home-mpv-configuration
          #:global (make-mpv-profile-configuration
                    #:fullscreen? #t
                    #:alang '("jpn" "eng"))))
    Variable: home-mpv-service-type
    This is the type of the mpv home service, whose value is a home-mpv-configuration object.
    Procedure: make-home-mpv-configuration
    Return a new instance of home-mpv-configuration. Available keyword arguments are:
    inherit (default: #t)
    Inherit fields from an another instance.
    global (default: (make-mpv-profile-configuration))
    The global configuration preceding all profiles.
    profiles (default: ())

    An alist containing configuration for any additional profiles to include in the configuration file. 

    (make-home-mpv-configuration
 #:profiles `((fullscreen . ,(make-mpv-profile-configuration
                              #:fullscreen? #t))))
    extra-config (default: #f)
    Additional content to include in the configuration file. It is placed at the end of the file.
    Procedure: make-mpv-profile-configuration

    Return a new instance of mpv-profile-configuration. As above, it also supports the #:inherit argument. Additionally it supports keyword arguments named after the options of mpv. Hence --fullscreen (or fullscreen in the configuration file) becomes #:fullscreen?.

    Few options are using their aliases instead. audio instead of aid, video instead of vid, sub instead of sid, screenshot-directory instead of screenshot-dir and watch-later-directory instead of watch-later-dir.

    Valid values for the fields depend on their type.

    Flags
    The value should be #f or #t.
    Numerical fields
    Integer and integer64 fields are validated by integer?, float and double fields by real?. Ranges are checked when applicable.
    Aspect
    Same as integer.
    ByteSize
    Same as integer64.
    Choice
    The value should be a symbol representing member of the enumeration. If the choice has ‘=or …=' part, it can also be value of that alternative type.
    type list
    The value should be a list of the type.

    Other types accept strings, with validation of the values where possible (e.g. type ‘=Color=' is validated, but type ‘=Audio channels or channel map=' is not). If an option is marked as taking a file, values satisfying file-like? can also be used.

    The full list of currently supported keyword arguments is below. For the types, allowed values and full description please refer to the mpv --list-options and mpv manual.

    Only set fields are output to the configuration file. Accessors are provided for every field, returning either their value or a sentinel object %unset-value (from (gnu services configuration)).

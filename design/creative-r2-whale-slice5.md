# Whale R2 — Slice 5/7: data & machine-output — seven signature sparks

> Fresh burn (2026-11-07): 7/7 sparks landed on `deepseek/deepseek-v4.1-flash` via the
> rebuilt `zen-whale-burn.mjs` rig (15,219 tok this salvo). Same design language and perf law as
> slices 1–2.

Design language (fixed): "A HUD, not a magazine" — ink-blue black #05070e, neon cyan / magenta / electric yellow, self-hosted Electrolize / Inter / JetBrains Mono, sharp corners with one notched edge, corner brackets on focus, circuit grid + scanlines, per-source neon hue via `--dn-src`.

PERF LAW: phones run ZERO animations; desktop at most 3 ambient loops per page; `prefers-reduced-motion` renders every spark's static end-state.

| 1 | Carry-Wire Checksum | The table does its own arithmetic in front of you — digit carries physically travel down the gutter, and the row earns its checksum. | Each data row is a CSS grid of mono digit cells (JetBrains Mono, tabular-nums) plus a trailing .checksum cell; a single absolutely-positioned <canvas> per table sits over the gutter at pointer-events:none. On focusin/value-change of a row (Svelte 5 $derived recomputes the real 16-bit checksum of the row's numeric payload), a one-shot 420ms pass sweeps columns right-to-left at 60ms stagger: each digit column flashes to --dn-src cyan for 90ms, and when that column's digit sum ≥10 the canvas draws a 1px quadratic carry arc (control point 18px above the midpoint) from the column's measured getBoundingClientRect x to the next-left column, stroked with a 0.35→0 alpha fade over 160ms and a 2px leading dot. The .checksum cell then resolves from 6 frames of scrambled hex (rAF, quantized to 70ms ticks) into the true value, and a 1px underline wipes in left-to-right in 120ms. All geometry is measured once per event and drawn on a canvas sized to devicePixelRatio, so zero layout thrash per frame. | none (one-shot) |

After 120ms, a 1px horizontal rule draws left-to-right across the matrix over 180ms with ease-out, then collapses into a small notched seal chip at the row’s trailing edge. No rAF, no interval, no canvas: one class toggle per write, `will-change:transform` applied per column for delay+duration then stripped in `transitionend`, `min-inline-size:1ch` locks layout so nothing reflows. | none (event-driven) |

## Perf & motion budget

**1. Carry-Wire Checksum** — loop slot: none (one-shot). Phones: Row renders with the final checksum hex already printed and no arcs or flashes — just the underlined mono value. Reduced motion: Identical static end-state: final checksum visible, arcs and column flashes never drawn, scramble replaced by instant swap.

**2. Parity Seal** — loop slot: none (event-driven). Phones: The final bit-matrix and notched seal chip paint instantly, with no flips or rule draw. Reduced motion: The final bit-matrix and seal chip render in one static paint with the verified hue fixed.

**3. Checksum Witness** — loop slot: none (event-driven). Phones: The checksum and final sparkline appear already settled in the gutter, with no typing or dash animation. Reduced motion: The final hex checksum and static sparkline render immediately, with no reveal, dash sweep, or typing.

**4. Carry-Cascade Readout** — loop slot: none (event-driven). Phones: Digits swap instantly as plain tabular-nums text; the filament renders once as a static 1px cyan rule under the number, then stays. Reduced motion: Same instant set with zero transition; columns that changed hold a static electric-yellow tint at rest until the next write, and no filament travels.

**5. Carry Filament** — loop slot: none (one-shot). Phones: Final digits render immediately with no filament or flip motion. Reduced motion: Final digits render immediately with a static 1px carry trace at 20% opacity for orientation.

**6. Ledger Cross-Section** — loop slot: none (event-driven). Phones: Sparklines render as static finished traces with the final-tick dot lit; tapping a row opens one static value tooltip, no ruler, no drag. Reduced motion: Hairline sits fixed at the last tick at 0.12 opacity, all dots lit at their final value, ruler is `pointer-events:none` and every readout is legible without any scrubbing.

**7. Decimal Carry Relay** — loop slot: none (one-shot). Phones: Shows the final number with ghost spans and carry rail removed, leaving only the changed digits in place. Reduced motion: Renders the new digit string immediately with no ghost motion and no rail, preserving only the final numeric state.

## Why it surprises

**Carry-Wire Checksum** — The animation IS the arithmetic — carries are drawn as physical wires between real digit columns, so the user watches addition happen rather than a decorative progress bar. Because the checksum is genuinely computed from the row's values, editing a cell makes the whole row visibly re-prove itself, turning a boring ledger into something with a pulse. It also only fires per-row on focus, so a 400-row table stays silent until you interrogate one line.

**Parity Seal** — Most checksum UI is just hex text; here the changed bits are visible scars that flip and settle, so data provenance feels physically stamped. The seal chip is earned by a tiny mechanical rule-draw, not a generic success toast. It turns machine verification into a per-row artifact you can scan without reading the hex.

**Checksum Witness** — The checksum is a real FNV-1a of the row's text, so two rows with identical numbers visibly twin themselves in hex — a quiet audit cue nobody expects from a hover state. The sparkline plots deltas rather than values, so a flat ledger row collapses into a single neon dot instead of a line, making 'no change' legible at a glance.

**Carry-Cascade Readout** — Only the digits that actually moved animate, so a +1 tick nudges one column while a 41,000 jump spins exactly two — the number reads as a gear train with heritable slack rather than a rolling blur. The carry filament is a fabricated 'data bus': a 1px cyan wire flashes above the column that borrowed and a yellow notch bites the edge, turning arithmetic into visible hardware. Neighbouring unchanged columns desaturate to 62% via `filter` for the transit, snapping attention to the moving digits without any spotlight overlay or additional DOM.

**Carry Filament** — It turns carry propagation — usually invisible integer bookkeeping — into a routed circuit trace that follows the actual table geometry. Resizing or reordering the ledger changes the path, so the arithmetic feels physically wired into the layout. The trace is also per-source hue-coded, making a totals column read like a live bus, not a spreadsheet.

**Ledger Cross-Section** — The table quietly photographs itself — releasing the ruler leaves a permanent ghost slice, so a later glance shows a timestamp you chose rather than 'now'. Scrubbing also exposes coincidence: rows that share a threshold at that tick bracket themselves in electric yellow and flash their `--dn-src` hues together, turning a passive ledger into a correlation detector. And the one anti-effect — cells use `font-variant-numeric: tabular-nums` in JetBrains Mono — means the digits never jitter as they mutate, which reads as unnervingly precise under a HUD that otherwise loves noise.

**Decimal Carry Relay** — Carries are invisible in normal interfaces, so animating only the 9→0 rollover makes arithmetic feel physically geared instead of merely ticking upward. The right-to-left relay order and brief yellow rail reveal the hidden column math, then vanish before the eye can fully parse them. It also stays quiet on ordinary +1 changes, making the rare carry boundary the actual spark.
